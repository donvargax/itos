# itos 0.6.0

## What is new

- **CI reads the tasks a range names from the ledger footer, whatever its key** (slice 18).
  `ci plan` and `ci run` read the tasks a pushed range names from every footer of
  `commits.footers` whose `source` is `ledger`. They used to read only a footer called `Task`, so
  a project calling its ledger footer anything else (`Work:`, say) got no task checks in CI, and
  the plan stopped on `itos.yaml has no commits.footers.Task`. With more than one ledger footer,
  the tasks of each are read; with none, a range names no task. The commit-msg hook already read
  them this way.
- **What itos prints names the ledger's folder and the prose steps as the config gives them**
  (slice 18):
  - `ci run`, for a footer naming a task the ledger lacks, says
    `No task <id> in <folder>/, though a footer names it`, the folder being the directory part of
    `ledger.files`, where it always said `tasks/`.
  - a prose-only range's first line names `ci.prose.steps`, each in backquotes:

    ```text
    Only prose changed: `vp check`, `itos config check`, and the named tasks' static and `prose: true` checks.
    ```

    where it always said `` `vp check`, and the named tasks' … ``, whatever the steps were. With
    no prose steps it reads `Only prose changed: the named tasks' static and …`.

  - the footer rule's fix for an unknown task (`--json`'s `fix`) names the ledger's folder,
    `name an id <folder>/ has, …`, where it always said `tasks/`.
  - `itos hook commit-msg --help` says the checks run for "each task a ledger footer names
    (Task: here)".

## Upgrading

Do these in order, in one session, then commit as your project's rules ask (the pin is a `build`
commit). No config key changed, so `itos.yaml` needs no edit to keep working. What can change is
what your next CI run does, if your ledger footer is not called `Task` (step 3), and some lines
of output, if your ledger is not under `tasks/` or your prose steps are not `vp check` (step 4).

1. **Use Node 24 or later** wherever itos runs, as for v0.5.0.

2. **Change the pin.** Check the tarball against its SHA-256, then point `package.json`'s `itos`
   dependency at the v0.6.0 URL (the lockfile records its integrity):

   ```sh
   url=https://github.com/donvargax/itos/releases/download/v0.6.0/itos-0.6.0.tgz
   curl -fsSLO "$url"
   echo "{sha256}  itos-0.6.0.tgz" | sha256sum -c -
   npm install --save-dev "$url"   # or: pnpm add -D "$url"
   ```

3. **If your ledger footer is not called `Task`, CI now runs the checks of the tasks it names.**
   They did not run in CI before. Before you push, run `itos task <id>` for the tasks your commits
   since the last green run name, and fix what is red. `itos ci plan <from> HEAD` lists them.

4. **Match the changed output.** Anything that reads itos's output must read:
   - `No task <id> in <folder>/, though a footer names it`, `<folder>` being `ledger.files`'
     directory, where it read `No task <id> in tasks/, …`. Unchanged for a ledger under `tasks/`.
   - ``Only prose changed: `<step>`, …, and the named tasks' static and `prose: true` checks.``,
     naming your `ci.prose.steps`, where it read ``Only prose changed: `vp check`, and …``.
     Unchanged when your prose steps are exactly `vp check`.
   - the unknown-task fix `name an id <folder>/ has, …` under `--json`, where it read
     `name an id tasks/ has, …`.

5. **Check:** `itos version` prints `itos 0.6.0`, and `itos config check` passes.
