# itos 0.2.0

The work registry moves beside the ledger, the commit-msg hook checks itos's own data as it is
staged, and every command itos starts goes through the configured shell.

## What is new

- **The registry's default home is `tasks/work-items.yaml`**, beside the ledger; `work.registry`
  still puts it anywhere else. With no registry where itos looks, `work`, `work check` and
  `config check` say "no work registry at <path>" (rule `work-registry-missing`, with a fix) and
  exit 1, where they failed with Node's ENOENT and exit 2.
- **`itos hook commit-msg` validates itos's data from the staged tree.** When a commit stages
  `itos.yaml`, a ledger file, the work registry or a smoke set (as the staged config names them),
  the hook runs `config check`'s problems over the index first and rejects the commit with them,
  one a line under `commits.reject_message`, exit 1. A commit staging none of them is not checked.
- **`shell` applies to every command itos starts**: task checks, CI steps, the header-lint
  delegates, range checks, the pre-push commands and the smoke run, as well as the providers and
  the command adapter, which were the only ones that read it.
- **`ci.stop_at_first_failure` is read.** Left out or true, `ci run` stops at the first failure,
  as before; false runs every step and check, prints "CI failed at: ..." for each failure and
  exits with the first one's code (`--json`'s `failed_at`).
- **A CI with no `tests:` step** reads no kind of named tests and no smoke set, so `ci run` no
  longer fails with "tests.scenario is missing" when the config has no `tests.scenario`.
- `ci run`'s line for a task not started names the registry the plan read.
- `itos version` and the package's version are one: package.json's.

## Known issues

- **The install lists an install script awaiting approval** (`p1-release-manifest`): the tarball
  carries this repository's package.json, whose `prepare: vp config` npm and pnpm report on
  install. Don't approve or run it: itos needs no install step, and it fails without Vite+. The
  manifest also declares no `engines`, though the bundle needs Node 24.
- **A `ledger.files` of `tasks/{group}.yaml` matches the new registry** (`p1-ledger-matches-registry`):
  with the default `ledger.group.pattern` (`[^/]+`), `tasks/work-items.yaml` is read as a ledger
  file, `config check` fails with "tasks/work-items.yaml is not a list of tasks" and `task list`
  with a TypeError. Such a project keeps its registry where the pattern does not reach (see
  Upgrading).
- **The commit-time check does not follow every file the data reads.** A commit that stages only
  `work.people`'s file (`CONTRIBUTORS.md`) can break the registry's owners
  (`p1-people-checked-at-commit`), and one that stages only feature files can break the smoke rule
  (`p1-smoke-rule-at-commit`): neither is checked until CI's `itos config check` or smoke step.
  `itos verify` re-checks pushed commits with the commit-msg rules but not this data check
  (`p1-verify-data-per-commit`).
- **A pre-commit hook's early exit is hand-written** (`p1-pre-commit-asks-what-skips`): a project
  that moves its registry or its ledger must change its hook's pathspec itself.
- **`shell: []` is accepted** (`p1-shell-not-empty`) and, now that every command goes through
  `shell`, makes every check, step and delegate fail with a message about a missing file. Leave
  `shell` out or give it at least one word.

## Upgrading

Do these in order, in one session, then commit as your project's rules ask (the pin is a `build`
commit; a registry moved together with an `itos.yaml` edit is one commit, of a type that may touch both, since
`config check` fails on the tree between two).

1. **Change the pin.** Check the tarball against its SHA-256, then point `package.json`'s `itos`
   dependency at the v0.2.0 URL (the lockfile takes its integrity):

   ```sh
   url=https://github.com/donvargax/itos/releases/download/v0.2.0/itos-0.2.0.tgz
   curl -fsSLO "$url"
   echo "{sha256}  itos-0.2.0.tgz" | sha256sum -c -
   npm install --save-dev "$url"   # or: pnpm add -D "$url"
   ```

   If `itos.yaml` sets `requires`, raise it to `>=0.2.0` once the config relies on anything below
   (the registry's new default above all).

2. **The registry: `work.registry`'s default moves from `docs/work-items.yaml` to
   `tasks/work-items.yaml`.** If `itos.yaml` sets `work.registry`, nothing moves. If it does not,
   and your registry is at `docs/work-items.yaml`, either:
   - move it: `git mv docs/work-items.yaml tasks/work-items.yaml`, and change every place that
     names the old path (the pre-commit hook's pathspecs, the docs, the agent instructions); or
   - keep it: set `work.registry: docs/work-items.yaml` in `itos.yaml`.

   If `ledger.files` is `tasks/{group}.yaml` (any pattern that matches `tasks/work-items.yaml`
   with your `ledger.group.pattern`), don't move it there: keep it at the old path with
   `work.registry`, or narrow `ledger.group.pattern` so it cannot match `work-items` (Known
   issues).

   **Tell whether you are affected: run `itos config check`.** "no work registry at
   tasks/work-items.yaml" (exit 1) means itos no longer finds your registry. Until that is fixed,
   `itos work` and `itos work check` fail the same way, and **`ci plan` and `ci run` change
   silently**: they read a missing registry as no task waiting, so the checks of tasks still
   `todo` (which `ci.wait_on_status` held back) run in CI and fail it. Fix the registry's path,
   then `itos config check` passes and those tasks wait again.

3. **`ci.stop_at_first_failure` is now read** (default true: it stops at the first failure, as v0.1.0 did).
   If `itos.yaml` sets it to false, `ci run` now goes on past a failure and runs everything; remove
   the line, or set it true, to keep stopping at the first.

4. **`shell` now applies to every command itos starts** (checks, CI steps, header-lint delegates,
   range checks, pre-push, the smoke run), not only the providers and the command adapter. If
   `itos.yaml` sets `shell`, every task check, CI step, `commits.header_lint` delegate, range
   check and `hooks.pre_push` command must run in it: run `itos ci run` once (or `itos task <id>`
   for a task) to see them do so. If `shell` is left out (`[sh, -c]`), nothing changes.

5. **The commit-msg hook can reject a commit that passed before.** When a commit stages
   `itos.yaml`, a ledger file, the registry or a smoke set, the hook rejects it with
   `config check`'s problems, read from the staged tree (not the working tree), including:
   - any problem `itos config check` already reports: a data file with one is now stopped at its
     next commit, so run `itos config check` after upgrading and fix what it says first;
   - `data-unreadable` when the index lacks a file the data names, such as the people file
     (`work.people`'s `CONTRIBUTORS.md`) left untracked while the registry is staged: commit the
     file. A config outside the repository (`ITOS_CONFIG`) is read where it is.

   It runs only if the commit-msg shim calls `itos hook commit-msg` (as `itos hooks install`
   writes it); a shim that calls commitlint directly does not get it, so rewrite it with
   `itos hooks install`.

6. **`ci run` with no `tests:` step no longer needs a `tests.scenario` kind.** If `itos.yaml`
   keeps a scratch `tests.scenario` (and a smoke file for it) only so `ci run` would start, remove
   both.

7. **Drop the pre-commit `itos config check` block**, the one that ran `itos config check` when
   `itos.yaml`, `tasks`, the registry or the smoke set was staged (T-022's): the commit-msg hook
   does it now, from the staged tree, which the working-tree check could not. The pre-commit
   hook's early exit can now skip `docs/**` and `tasks/**` as a whole (not only their Markdown),
   since itos's data there is checked at commit-msg:

   ```sh
   if [ -z "$(git diff --cached --name-only --diff-filter=ACMRD -- . ':(exclude)*.md' ':(exclude)docs/**' ':(exclude)tasks/**' ':(exclude)features/**/*.feature')" ]; then
   	exit 0
   fi
   ```

   Keep your registry's path inside what the exit skips, if you moved it elsewhere.

8. **Check:** `itos version` prints `itos 0.2.0`, and `itos config check` passes.
